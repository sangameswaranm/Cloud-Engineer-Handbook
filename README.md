# Cloud-Engineer-Handbook

A living engineering handbook for a six-month Senior Cloud Engineer program.
The goal is **demonstrable engineering capability**, not certificates.

**Method:** Learn → Execute → Break → Troubleshoot → Document → Project → Assess

## Where things are

| File | Purpose |
|---|---|
| [ROADMAP](docs/ROADMAP.md) | Six-month plan (Month 1 is calibration) |
| [PROGRESS](docs/PROGRESS.md) | Evidence-based dashboard per domain |
| [DAILY-LOG](docs/DAILY-LOG.md) | Every study session, as it happened |
| [DECISIONS](docs/DECISIONS.md) | Decisions and the reasons behind them |
| [LAB-ENVIRONMENT](docs/LAB-ENVIRONMENT.md) | What the labs run on |
| [COST-CONTROL](docs/COST-CONTROL.md) | Cloud spend rules and cleanup log |

Topic notes live in `docs/01-Linux` … `docs/18-Architecture`; projects live in `docs/projects/`.

## Public repo rule

This repository is public. Real-world incidents are used as training material, but every client name,
hostname, domain, user ID, IP address and ticket number is replaced with a neutral placeholder
(for example `prod-app-01`, `example.internal`) before it is committed.
